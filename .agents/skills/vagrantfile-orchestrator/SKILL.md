# Vagrantfile Orchestrator

<constraint>
The `SCRIPTS` array in `Vagrantfile:72-88` is the single source of ordering truth — Vagrant executes provisioners in declaration order regardless of script filename. Never rely on numeric prefix ordering without a matching array entry.
</constraint>

<constraint>
The base box MUST be `bento/debian-13`. `debian/trixie64` is libvirt-only (Debian bug #1110834); `debian/testing64` tracks Forky (Debian 14 dev) where Tilix and other packages get auto-removed. Source: `Vagrantfile:91`, `CLAUDE.md`.
</constraint>

<constraint>
The graphics controller MUST be `vmsvga`. VBoxSVGA is Windows-only and causes black screen from boot on Linux guests. Source: `Vagrantfile:105`.
</constraint>

## When to Use

- Adding a new script to the provisioning chain.
- Reordering provisioning steps.
- Changing VM resources (RAM, CPUs, VRAM, audio).
- Switching between local-dev (`VAGRANT_SCRIPTS_DIR=./scripts`) and remote-fetch modes.
- Passing a new env var to all provisioners.
- Understanding the curl bootstrap in the inline runner.
- Tracing how `FORCE_REINSTALL=1` reaches guest scripts.

## Core Patterns

### Two-mode fetch dispatch

```ruby
SCRIPTS_REPO = "docksdocks/vagrant"
SCRIPTS_REF  = ENV.fetch("VAGRANT_SCRIPTS_REF", "main")
LOCAL_DIR    = ENV["VAGRANT_SCRIPTS_DIR"]
```

Source: `Vagrantfile:68-70`

```bash
if [ -n "${VAGRANT_SCRIPTS_DIR:-}" ]; then
  export VAGRANT_LIB_PATH=/vagrant/scripts/_lib.sh
  bash /vagrant/scripts/#{name}.sh
else
  # ... curl bootstrap ... fetch and run /tmp/#{name}.sh
fi
```

Source: `Vagrantfile:138-160`

Setting `VAGRANT_SCRIPTS_DIR=./scripts` (host-side env) switches every script and asset fetch to local disk, enabling iteration without a push-to-test cycle.

### SCRIPTS array — the ordering manifest

```ruby
SCRIPTS = %w[
  10-apt-repos
  20-packages
  30-guest-additions
  40-xfce-base
  41-xfce-theme
  50-vboxclient-supervisor
  51-vbox-autoresize
  60-apps-tilix-mousepad
  65-superfile-fonts
  70-nodejs-claude
  80-git-ssh-lazygit
  85-secrets-env
  90-claude-config-sync
  95-permissions
  99-finalize
]
```

Source: `Vagrantfile:72-88`. Every `config.vm.provision` entry is generated by `SCRIPTS.each do |name|` at line 119. Adding, removing, or reordering is a single-line change here.

### Inline runner — curl bootstrap + _lib.sh cache

```bash
if ! command -v curl >/dev/null 2>&1; then
  export DEBIAN_FRONTEND=noninteractive
  apt-get update -qq
  apt-get install -y -qq curl ca-certificates
fi
export VAGRANT_LIB_PATH=/tmp/vagrant-_lib.sh
if [ ! -f "$VAGRANT_LIB_PATH" ]; then
  curl -fsSL --retry 4 --retry-delay 2 \
    "https://raw.githubusercontent.com/#{SCRIPTS_REPO}/#{SCRIPTS_REF}/scripts/_lib.sh" \
    -o "$VAGRANT_LIB_PATH"
fi
```

Source: `Vagrantfile:144-155`. The bento/debian-13 minimal image ships without curl. The inline runner bootstraps it before the first real script runs, then caches `_lib.sh` at `/tmp/vagrant-_lib.sh` — shared across all 15 script executions in one provision run.

### env passthrough to all provisioners

```ruby
env = {
  "SCRIPTS_REPO"        => SCRIPTS_REPO,
  "SCRIPTS_REF"         => SCRIPTS_REF,
  "VAGRANT_SCRIPTS_DIR" => LOCAL_DIR,
  "FORCE_REINSTALL"     => ENV["FORCE_REINSTALL"],
}.compact
```

Source: `Vagrantfile:120-128`. `.compact` drops nil — so `FORCE_REINSTALL` is absent from the guest env when unset. Scripts check `${FORCE_REINSTALL:-0}`.

### VirtualBox customize block

```ruby
vb.customize ["modifyvm", :id, "--vram", "256"]
vb.customize ["modifyvm", :id, "--graphicscontroller", "vmsvga"]
vb.customize ["modifyvm", :id, "--clipboard-mode", "bidirectional"]
vb.customize ["modifyvm", :id, "--draganddrop", "bidirectional"]
vb.customize ["modifyvm", :id, "--audio-driver", detect_audio_driver]
```

Source: `Vagrantfile:104-108`. 256 MB is the hard VMSVGA ceiling (silently clamped above that). See virtualbox-vmsvga-gotchas skill for full rationale.

### /tmp sticky-bit defensive chmod

```bash
chmod 1777 /tmp
```

Source: `Vagrantfile:132-135` (inline runner, before script execution). bento/debian-13 ships `/tmp` correctly, but earlier base boxes did not; this is defensive for compatibility and costs nothing.

## Key Decisions

- **`SCRIPTS` array = single ordering authority**: Vagrant executes in declaration order; numeric prefixes are cosmetic. Source: `plans/0002-split-vagrantfile.md:44`.
- **Ref pinning via `VAGRANT_SCRIPTS_REF`**: defaults to `main`; pin to a tag (`v1.0.0`) for reproducible production boxes. Source: `Vagrantfile:69`.
- **`_lib.sh` cached at `/tmp/`**: avoids 15 separate network fetches per provision run; all scripts share the same download. Source: `Vagrantfile:150-155`.
- **`bento/debian-13` is the only valid base box**: libvirt-only and Forky-tracking alternatives are both broken for different reasons. Source: `Vagrantfile:91`.
- **Host carve-out for 16 GB / 8-CPU hosts**: these hosts allocate 6656 MB / 4 vCPU to avoid starving host Chrome+Claude. Source: `Vagrantfile:53-54`.

## Gotchas

**Switching to `debian/trixie64`**: fails on VirtualBox hosts with "No usable default provider could be found" — the box is libvirt-only. Source: `Vagrantfile:91`, `CLAUDE.md`.

**Changing `vmsvga` to `vboxsvga`**: causes black screen from boot on Linux guests — VBoxSVGA requires the `vboxvideo` driver which does not load on Debian 13. Source: `Vagrantfile:105`.

**Adding a script file without updating `SCRIPTS` array**: the file is never executed. Vagrant only runs provisioners declared in the array.

**`VAGRANT_SCRIPTS_DIR` set but pointing at a directory without the script**: the condition `[ -n "${VAGRANT_SCRIPTS_DIR:-}" ]` is true, so it runs `bash /vagrant/scripts/#{name}.sh` — which fails if the script doesn't exist locally. Always add the file to `scripts/` before adding it to `SCRIPTS`.

**`_lib.sh` cached at `/tmp/vagrant-_lib.sh`**: the cache persists across `vagrant provision` runs within the same VM session. If `_lib.sh` changes (new helper added), the old cached copy is used until the VM reboots or the file is manually deleted. During development, use `VAGRANT_SCRIPTS_DIR=./scripts` mode which reads `_lib.sh` directly.
